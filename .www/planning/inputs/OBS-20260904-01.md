# OBS-20260904-01 — Observability View 개발 입력

- 수신 시각: 2026-09-04 03:39 KST (session display context)
- 수신 경로: 현재 WWW 개발 세션의 사용자 Chat 입력
- 연결 Epic: `EP-019`
- 입력 형태: 세 개의 사양을 한 사용자 메시지에 순서대로 결합
- 보존 수준: 요구사항·금지사항·검증 항목의 정규화 기록. raw conversation 정본은 원래 session journal이 소유한다.

## 입력 1 — Observability View Architecture

Stats / Dashboard / Monitor를 하나의 View Family로 정의한다.

- Monitor: 현재 runtime과 active execution
- Stats: 한 session의 retrospective review
- Dashboard: 여러 session/project/time range의 aggregate overview
- canonical fact는 Journal / Receipt / Usage이며 View별 중복 수집을 금지한다.
- `/stats`, `/dashboard`, `/monitor` 직접 진입
- workspace 내부 `r` next, `Shift+R` previous, `1/2/3` direct 이동
- sibling 이동은 navigation history를 쌓지 않으며 `Esc`는 workspace 진입 전 화면으로 한 번에 복귀
- editable input focus에서는 문자 shortcut을 가로채지 않음
- View 이동은 journal activity를 추가하지 않음
- context selection은 가능한 범위에서 유지하고 관측 불가능한 historical monitor state는 만들지 않음
- 구현 전에 projection boundary, navigation state, keyboard routing, ASCII architecture와 test plan을 보고하고 승인받음

## 입력 2 — Aggregate Dashboard Design

Dashboard는 Session Stats 확대판이 아니라 다중 session/project 집계 화면이다.

- STATUS / USAGE / TREND / ATTENTION / RECENT 정보 위계
- KPI 최대 4~5개: active, completed, tokens, failures, 필요 시 blocked
- aggregate model usage는 visual bar 필수
- trend는 충분한 실제 bucket이 있을 때만 2~3개 표시
- 임의 Efficiency Score 금지
- attention threshold는 기존 계약 또는 명시적 기준만 사용
- recent session은 한 row이며 Stats drilldown entry point
- active session의 Monitor handoff는 runtime 지원 범위만 제공
- 기간을 신뢰할 수 없으면 Today/7 days를 가장하지 않고 observed coverage를 표시
- wide/normal/narrow responsive 계약과 실제 journal 기반 mockup을 구현 전에 승인받음

## 입력 3 — Live Runtime Monitor

Monitor는 “바로 지금 WWW에서 무슨 일이 일어나는가?”에만 답한다.

- state, session/request, agent/model/tool, elapsed, approval/wait, retry/failure, recent semantic activity
- raw log/prompt/response/stack trace 금지
- progress를 모르는 tool에 percentage bar 금지; indeterminate elapsed 표현 사용
- recent activity window는 bounded 8~15 events
- idle/running/waiting/blocked/failed/completed 상태는 symbol + text
- event-driven update 우선, 불가능한 경우 bounded polling
- `r`은 refresh가 아니라 View rotation으로 예약
- 완료 후 Stats review로 자연스럽게 이동
- 구현 전에 source/subscription/schema/state machine/normalization/mockup/refresh/navigation/test를 승인받음

## 공통 수락 기준

- 세 View가 동일 사실을 서로 다르게 수집하지 않는다.
- 같은 metric 이름은 같은 정의를 사용한다.
- raw 내용보다 상태·수치·관계가 우선한다.
- 관측 불가능한 값은 unknown/unavailable이며 추정하지 않는다.
- 구현은 이 입력과 승인된 architecture receipt를 source로 추적한다.
