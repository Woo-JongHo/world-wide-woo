# WOO-689 · 04. 긴 결과를 안정적으로 탐색한다

Linear 본문을 얇게 정리하기 전의 상세 요구·기록을 보존한다. 상태는 기록 시점의 것이며 최신 구현은 [PR #46](https://github.com/Woo-JongHo/world-wide-woo/pull/46)과 [[2026-09-07-Chat-Completion-Verification]]에서 확인한다.

## 결과

긴 코드·다국어 답변을 읽을 때 내용과 읽던 위치를 잃지 않고, 새 출력이 들어와도 편하게 탐색한다.

## 범위

### 기능

* 완료 답변은 공개용 정제 후 전체 본문을 탐색할 수 있게 한다. live draft 제한, 화면 viewport, 저장 데이터의 보존 정책은 구분한다.
* live draft나 공개 출력이 제한되면 생략 사실을 표시한다. 전체 내용이 아직 수신되지 않은 상태를 전체 원문처럼 안내하지 않는다.
* 한글/CJK·emoji·결합문자·긴 URL·탭·ANSI 정제 결과를 terminal 표시 폭에 맞춰 처리한다.
* 위로 스크롤하여 과거 답변을 읽을 때 자동 추적을 풀고, 최신 위치 복귀 시 다시 따라갈 수 있게 한다.
* resize 이후에도 가능한 한 읽던 메시지를 유지한다. 패널 배치·focus·키 처리 계약은 [WOO-680](https://linear.app/woo-world/issue/WOO-680/layout) Layout과 맞춘다.
* 스크롤만 바뀌면 기존 projection을 재사용한다. 5,000개 메시지에서 최초 렌더·스크롤·resize 비용을 나눠 기록한다.

## 완료 조건

- [ ] 40·80·120열과 연속 resize에서 표시 행이 Chat 폭을 침범하지 않는다.
- [ ] 긴 완료 본문의 앞·중간·끝이 탐색 가능하고 코드 줄·문단 순서가 보존된다.
- [ ] 과거 답변 탐색 중 streaming을 받아도 강제로 끝으로 이동하지 않는다.
- [ ] 최신 위치 복귀와 focus 전환을 실제 TUI에서 확인한다.
- [ ] 변경 전 5,000개 메시지·긴 코드 사례의 성능 기준선을 먼저 측정한다. 메시지 수·UTF-8 bytes·terminal 크기·기기·렌더 지연을 기록하고 같은 환경의 변경 후 결과와 비교한다.

검증 시작점: `test/workbench-views.test.ts`, `test/workbench-shell-policy.test.ts`. 성능 수치는 실측 전 통과값으로 적지 않는다.

현재 draft의 화면 제한은 16,384 JS 문자열 길이 / 120행이며 assistant 완료 본문에는 같은 제한을 적용하지 않는다. 사용자 메시지·대기 입력·오류에는 별도의 제한된 표시가 적용된다. shell이 사용하는 dashboard-layout에는 end-follow viewport, 테스트에는 스크롤 중 자동 추적 방지 사례가 있다. 2026-09-06의 `99_www` 작업 트리(미커밋 변경 포함)를 읽은 기준이다. 코드 링크는 `main` 탐색용이며 로컬 변경의 배포·수락을 뜻하지 않는다. 아래 완료 기준은 앞으로 확인할 항목이다.
