# WOO-679 · [Chat] 대화·실행·결과를 읽기 좋은 하나의 흐름으로 보여준다

Linear 본문을 얇게 정리하기 전의 상세 요구·기록을 보존한다. 상태는 기록 시점의 것이며 최신 구현은 [PR #46](https://github.com/Woo-JongHo/world-wide-woo/pull/46)과 [[2026-09-07-Chat-Completion-Verification]]에서 확인한다.

## 목적

대화의 내용에 집중하면서 **누가 말했고, 무엇을 실행 중이며, 어떤 결과로 끝났는지** 편하게 읽는 Chat을 만든다.

## 범위와 원칙

* 사용자 입력은 낮은 대비의 배경으로 구분하고, Agent 답변은 열린 배경과 충분한 문단 여백으로 보여 준다.
* 본문을 가장 잘 읽히게 하고, 실행·상태·메타 정보는 보조 위계로 둔다. 같은 종류의 내용은 시작선·간격·문구를 통일한다.
* 기존 semantic theme을 사용하고, 성공·실패·중단을 색과 함께 문자·기호로 구분한다.
* 긴 출력 중 과거 내용을 읽을 때 위치를 유지한다. 생략 사실과 전체 내용의 확인 경로를 분명히 한다.
* 결과 요약은 같은 요청에서 관측된 사실만 보여 준다. 명령 성공을 검증·업무 수락 완료로 확대하지 않는다.

## Chat 전체에서 마무리할 일

- [ ] 메시지·실행·최종 답변을 하나의 자연스러운 흐름으로 배치하고 같은 실행의 갱신을 중복 카드로 쌓지 않는다.
- [ ] Tool·파일 변경은 이름·대상·결과를 간결하게, 승인 대기·전송 대기·오류는 발화와 구분해 표시한다.
- [ ] 현재 구현의 같은 root thread·turn 완료 후 결과 요약 1회 표시를 회귀 확인한다. 최종 메시지 미수신 시에는 정상 결과로 꾸미지 않고 누락 상태를 드러낸다.
- [ ] 선택한 실행의 상세 내용은 Tracer로 연결하고 원본 부재는 확인 불가로 표시한다.
- [ ] 스크롤·resize·focus 전환에서도 읽던 위치와 입력 접근성을 유지한다.

## 완료 조건

짧은 답변, 여러 실행이 섞인 대화, 실패·중단, 재개를 실제 TUI에서 확인한다. 40·80·120열과 색상 제한 환경에서 역할·내용·상태가 구별되고, 관련 하위 작업과 위 통합 항목의 자동 검증·화면 확인 근거가 있어야 한다.
