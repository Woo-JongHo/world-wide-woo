# WOO-688 · 03. 답변 생성·완료·중단 과정을 보여준다

Linear 본문을 얇게 정리하기 전의 상세 요구·기록을 보존한다. 상태는 기록 시점의 것이며 최신 구현은 [PR #46](https://github.com/Woo-JongHo/world-wide-woo/pull/46)과 [[2026-09-07-Chat-Completion-Verification]]에서 확인한다.

## 결과

답변이 만들어지는 동안 읽던 흐름을 유지하고, 종료 원인과 마지막 내용을 정확히 확인한다.

## 범위

### 기능

* 같은 Native item의 delta는 같은 응답에 이어 붙인다. 완료 payload가 오면 최종값을 반영하고 draft와 완료 본문을 동시에 중복 표시하지 않는다.
* 생성 중에는 진행 상태를 보여 주며, 중단 조작은 현재 shell에서 실제 사용할 수 있는 경로로 안내한다.
* 실패·중단 시 이미 받은 부분 답변을 남기고 상태를 표시한다. 빈 응답과 정상 완료를 혼동하지 않는다.
* 늦은 delta·중복 completed·다른 item의 이벤트가 끝난 응답이나 다른 답변을 덮어쓰지 않도록 한다.
* 본문·상태·폭 변화에 맞춰 표시 캐시를 갱신하고 단순 스크롤에서는 기존 projection을 재사용한다.

## 완료 조건

- [ ] 시작 → 여러 delta → completed에서 최종 답변이 한 번 표시된다.
- [ ] delta 이후 실패·취소에서도 부분 답변과 종료 상태를 확인한다.
- [ ] final message observation 없이 turn 종료만 수신해도 받은 부분 답변을 잃지 않고 최종 본문 미수신 상태를 안내한다.
- [ ] 같은 completed 재수신, 완료 후 late delta, 다른 item delta를 각각 재현해 내용 오염이 없음을 확인한다.
- [ ] 내용이 같아도 streaming → completed 시 공개 응답 정제가 다시 적용된다.
- [ ] 실제 TUI 녹화에서 과도한 깜빡임·화면 이동 없이 진행과 종료를 읽는다.

검증 시작점: `test/project-workbench.test.ts`, `test/workbench-views.test.ts`, `test/project-workbench-session.test.ts`.

* [src/infrastructure/project-workbench-session.ts](<https://github.com/Woo-JongHo/world-wide-woo/blob/main/src/infrastructure/project-workbench-session.ts>) — Native session event 전달
* [src/presentation/tui/workbench-views.ts](<https://github.com/Woo-JongHo/world-wide-woo/blob/main/src/presentation/tui/workbench-views.ts>) — update / renderMessage / draftMarkdown: 본문·상태·캐시 표시

현재 delta는 bounded live draft에만 쌓이며 메시지 원문으로 journal에 저장되지 않는다. final message observation 없이 turn 종료만 오면 draft가 지워져 부분 답변이 남지 않을 수 있는 코드 경로가 있다. 이 경우의 보존·미수신 안내를 이번 작업에서 보완한다. 현재 draft와 완료 메시지는 별도 표시 경로다. 따라서 동일 UI row가 전 과정에서 유지된다고 단정하지 않고, 전환 시 사용자에게 중복·역전·읽던 위치 손실이 없는지를 수락 기준으로 삼는다. 2026-09-06의 `99_www` 작업 트리(미커밋 변경 포함)를 읽은 기준이다. 코드 링크는 `main` 탐색용이며 로컬 변경의 배포·수락을 뜻하지 않는다. 아래 완료 기준은 앞으로 확인할 항목이다.
