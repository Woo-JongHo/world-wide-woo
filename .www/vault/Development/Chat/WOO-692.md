# WOO-692 · 07. 실제 TUI에서 가독성과 상태 전환을 검증한다

Linear 본문을 얇게 정리하기 전의 상세 요구·기록을 보존한다. 상태는 기록 시점의 것이며 최신 구현은 [PR #46](https://github.com/Woo-JongHo/world-wide-woo/pull/46)과 [[2026-09-07-Chat-Completion-Verification]]에서 확인한다.

## 결과

개별 테스트를 통과한 Message가 실제 터미널에서도 편하게 읽히고 안정적으로 동작하는지 종합 확인한다. 하위 기능의 unit test를 대신하는 작업이 아니라 Message를 수락하기 위한 통합 검증이다.

### 실행과 근거

1. 기준 commit, 미커밋 diff 여부, OS·terminal·색상 설정·크기를 기록한다.
2. 40·80·120열에서 동일 대표 대화를 실행하고 좁은 폭 ↔ 넓은 폭 전환을 기록한다.
3. 자동 회귀 검증은 현재 Native Workbench 경로를 대상으로 실행한다. legacy TranscriptView 검증만으로 대체하지 않는다.
4. 실제 TUI 캡처 또는 녹화로 시작·생성 중·완료·실패·재개를 남긴다. fixture와 실제 Native event 검증을 구별한다.
5. 성능·resize 결과는 이 통합 검증에서 같은 조건으로 기록하고, 개별 기능의 구현 이슈를 수락 근거로 재사용하지 않는다.
6. 하위 이슈에서 남긴 유효한 화면·자동 검증 근거는 재사용한다. 실패는 원인 이슈에 연결하고 수정 후 영향을 받은 시나리오를 다시 확인한다.

## 완료 조건

- [ ] 위 시나리오의 실제 결과·기대 결과·근거 경로를 표로 남긴다.
- [ ] 가독성은 역할 구분, 시작선·여백, 코드 강조, 상태 식별, 긴 내용 탐색을 각각 판정한다.
- [ ] 자동 검증 통과와 실제 화면 수락을 별도로 기록한다.
- [ ] 남은 결함과 미실행 환경을 명시하고 필수 시나리오가 빠지면 완료 처리하지 않는다.

현재 이슈 본문을 정의한 단계이며, 위 테스트나 실제 화면 검증을 수행했다는 의미는 아니다.
