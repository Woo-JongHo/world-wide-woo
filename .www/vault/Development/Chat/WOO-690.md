# WOO-690 · 05. 재개 뒤에도 대화 순서와 대상을 유지한다

Linear 본문을 얇게 정리하기 전의 상세 요구·기록을 보존한다. 상태는 기록 시점의 것이며 최신 구현은 [PR #46](https://github.com/Woo-JongHo/world-wide-woo/pull/46)과 [[2026-09-07-Chat-Completion-Verification]]에서 확인한다.

## 결과

세션을 닫았다 열거나 연결이 끊겨도, 같은 질문과 답변을 중복·뒤섞임 없이 다시 읽는다.

## 범위

### 데이터와 연결 기준

* Native thread·turn·item이 대화 소속을 결정한다. `ProjectActivity.id`는 개별 관측 기록을 가리키며 같은 item의 갱신마다 달라질 수 있다.
* 현재 모듈 함수 `projectChat(activities)`는 `itemId ?? activity.id`로 메시지를 묶고 최신 record를 `activityId`로 연결한다. 같은 이름의 클래스 메서드는 여기에 전송 전 local 메시지를 합친다. 전체 context에서는 thread·turn도 함께 검증한다.
* UI identity를 메시지 본문이나 배열 순번으로 만들지 않는다. 같은 문장의 반복 질문도 서로 다른 전송이면 유지한다.
* append-only 기록 순서와 Native refs로 재개 시 화면 순서를 복원한다. 표시 대상의 최신 record 참조와 메시지의 지속 identity를 혼동하지 않는다.
* 낙관적 전송은 Native 수신 확인 후 해당 기록과 합친다. 수신 여부가 불명확하면 자동 재전송이나 성공 표시로 덮지 않는다.

현재 재개는 해당 thread의 local journal을 복원하며 provider의 과거 대화를 채워 넣지 않는다(`historyHydrated: false`, `partial-local-journal`). Native 조회는 현재 실행·전송 상태 정합에 사용한다. 로컬에 없는 과거 메시지는 복원 완료로 주장하지 않고 표시 범위를 안내한다.

### 기능

* 동일 전송의 local 상태 → durable 기록 전환에서 사용자 메시지가 두 번 나타나지 않게 한다.
* replay·재연결·잘린 Native history에서도 보유한 기록의 순서와 질문 연결을 유지한다.
* 다른 thread·child thread의 발화를 현재 root 대화로 잘못 합치지 않는다.
* 선택한 메시지의 Source가 갱신돼도 동일 대상의 기록을 찾아가게 한다. 원본을 찾을 수 없으면 확인 불가를 표시한다.

## 완료 조건

- [ ] 정상 재개, 중단 뒤 재개, truncated history에서 보유 기록의 메시지·질문 번호·소속 turn을 대조하고 local journal 범위를 안내한다.
- [ ] 같은 문장을 두 번 보낸 사례와 같은 이벤트를 두 번 받은 사례를 구별한다.
- [ ] 수신 불확실 전송의 확인·해소 뒤 사용자 메시지가 중복되거나 사라지지 않는다.
- [ ] 두 thread에서 item ID가 겹치는 경우와 child activity가 섞인 경우를 검사한다.
- [ ] 재개 요청 ID와 반환 thread ID가 다른 응답은 감지하여 다른 대화의 journal·Source가 섞이지 않게 한다.
- [ ] 재개 전후 표시 순서와 Native refs·activity 참조를 자동 검증 결과로 남긴다.
