# 목적

Todo 저장 실패·충돌 중에도 Chat을 계속 사용하고 마지막 신뢰 가능한 상태와 복구 시점을 이해하는 요구를 기록한다.

# 배경과 결정

내부 예외 원문보다 사용자 영향과 지원되는 다음 행동을 우선한다. 충돌은 최신 저장 내용을 덮어쓰지 않으며 무제한 즉시 재시도하지 않는다.

2026-09-07 초안 당시 `TodoLedger`는 Code-011 등록 전 후보였다. 현재 `src/system/services/todo-ledger.ts`의 이름 있는 최상위 class `TodoLedger`에 ` Code-011`이 선언되어 있고, frontmatter UUID와 traceability-v2 원장이 일치한다.

스냅샷 기준 상태는 `Todo`, parent는 `WOO-682`이며 제목과 보호 메타데이터는 변경하지 않는다.

# 상세 동작

enqueueNativeTodoSync는 저장 전 syncing을 게시하고 queue를 직렬화한다. 성공하면 document.updatedAt을 confirmed로 기록한다. 일반 실패는 ‘계획을 저장하지 못했습니다’, CAS conflict는 ‘다른 편집과 충돌했습니다’ 요약을 blocked 상태와 actionResult에 넣고 Chat 처리를 계속한다. 다음 관련 Plan 관측이 queue를 다시 구동한다.

# 예외

store read까지 실패해도 충돌을 성공으로 만들지 않는다. 내부 오류에 secret이 있을 수 있으므로 원문을 화면에 복제하지 않는다. 외부 편집을 자동 덮어쓰지 않는다.

# 테스트 방법

저장 지연, rejection, CAS conflict를 주입해 workbench phase·actionResult·snapshot·draft를 비교한다. 원인 해소 뒤 다음 Plan 관측으로 confirmed가 되는 시나리오를 추가하고 사용자용 문구를 명시적으로 assert한다.

# 실제 결과

현재 구현은 Chat을 기다리지 않고 사용자용 요약을 표시한다. 2026-09-07 실행에서 121 pass/1 fail이며, 유일한 실패는 테스트가 여전히 `sync rejected` 내부 문자열을 기대하기 때문이다. 이 실패는 구현과 회귀 계약의 불일치로 남아 있다.

# 남은 항목

테스트 기대를 안전한 요약 계약에 맞추고, 복구 성공 뒤 blocked 해제와 lastConfirmedAt 갱신, 실제 Native TUI에서 draft·대화 지속을 검증해야 한다.
