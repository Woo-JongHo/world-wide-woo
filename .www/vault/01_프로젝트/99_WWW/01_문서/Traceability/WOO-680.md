# 목적

화면 크기와 화면 종류가 바뀌어도 읽던 패널, 작성 중 입력, 선택과 focus를 유지하는 Layout 통합 요구를 재현 가능하게 기록한다.

# 배경과 결정

Layout은 배치·viewport·focus·복귀만 소유하고 Chat·Todo·Tracer의 상태 의미와 업무 수락은 각 기능에 남긴다. wide/compact 전환과 보조 화면 왕복을 하나의 사용자 흐름으로 묶되 하위 이슈의 검증을 통합 수락 근거로 재사용한다.

2026-09-07 초안 당시 `createDashboardLayout`의 Code-013 등록은 미완료였다. 현재 `src/tui/layout/dashboard-layout.ts`의 이름 있는 최상위 function `createDashboardLayout`에 ` Code-013`이 선언되어 있고, 같은 파일의 `ChatScrollView`는 기존 Code-003 identity를 유지한다.

스냅샷 기준 상태는 `Backlog`, parent는 `WOO-674`이며 제목과 보호 메타데이터는 변경하지 않는다.

# 상세 동작

`createDashboardLayout`은 폭 88열·높이 14행을 경계로 wide HStack과 compact 단일 ScrollView를 전환한다. wide는 Chat, 우상단 Source/T-note, 우하단 Todo를 독립 ScrollView로 유지한다. `ChatScrollView`는 follow-tail 또는 anchor+fraction을 기록하고 모드 전환 뒤 대상 viewport의 다음 layout에서 복원한다. Workbench shell은 동일 layout 객체를 보조 화면 전환 중에도 유지한다.

# 예외

anchor 텍스트를 다시 찾지 못하면 fraction으로 복원해야 하며, 0에 가까운 폭·낮은 높이에서도 음수 폭과 접근 불가능한 필수 영역이 생기지 않아야 한다. overlay 닫기는 승인 결정이 아니고, focus 복구 실패가 draft 삭제로 이어져서는 안 된다.

# 테스트 방법

`test/dashboard-layout.test.ts`와 `test/workbench-shell-policy.test.ts`로 wide/compact 구성, 독립 viewport, 낮은 높이 접근, 폭 제한, view host 객체 보존을 확인한다. 추가로 120→80→40→120열과 13↔14행을 실제 Native TUI에서 반복하며 scroll anchor·draft·focus를 기록한다.

# 실제 결과

2026-09-07 현재 대상 두 테스트 파일은 33 pass/0 fail이다. 구현에는 mode 전환 시 읽기 위치 전달과 width 제한이 있다. 다만 실제 resize 왕복, overlay 뒤 focus, 무채색·한글·emoji 수락을 모두 입증하는 화면 근거는 확인되지 않았다.
