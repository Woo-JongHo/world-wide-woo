# 목적

Chat·Todo·T-note에서 같은 실행 Source를 열고 이전 읽기·입력 맥락으로 복귀하는 요구를 기록한다.

# 배경과 결정

Tracer는 기능명, Source는 선택 activity 화면명이다. `/source`는 exact activity, `/trace`는 Plan membership까지 확인한다. 공통 focus/resize는 Layout을 재사용한다.

대표 후보는 `src/application/development-service.ts`의 이름 있는 최상위 class `DevelopmentService`다. 현재 선언과 traceability-v2 원장에는 Code-012가 아직 없으며, 이 UUID는 향후 원장 등록을 위한 초안 값이다.

스냅샷 기준 상태는 `Todo`, parent는 `WOO-681`이며 제목과 보호 메타데이터는 변경하지 않는다.

# 상세 동작

ProjectWorkbench의 `selectActivity`와 `selectTraceActivity`는 domain resolver 결과가 성공할 때만 selectedActivityId를 바꾼다. shell은 accepted receipt 뒤 Source mode로 전환하고 source layout leftScroll에 focus를 준다. Workbench view는 `/source`와 `/trace` 주소를 공개 행에 표시한다.

# 예외

없는 ID나 잘못된 Plan association은 다른 latest Source로 대체하지 않고 기존 선택을 유지한다. 새 출력 중 왕복이 draft를 초기화해서는 안 된다.

# 테스트 방법

shell policy와 trace-selection 테스트로 exact 선택·거절·mode 전환을 확인한다. Chat·Todo·T-note 각 진입점에서 Source identity, clear/Esc 복귀, draft·scroll을 실제 TUI로 비교한다.

# 실제 결과

명령 기반 exact selection과 Source mode 전환 경로는 구현·테스트에 있다. 각 화면에서 ID를 직접 입력하지 않는 발견 가능한 진입과 실제 왕복 focus/draft 근거는 확인되지 않았다.

# 남은 항목

세 화면의 직접 진입 UI, clear/Esc 복귀 상태, 새 출력 중 draft 유지와 Code-012 대표 연결을 완성해야 한다.
