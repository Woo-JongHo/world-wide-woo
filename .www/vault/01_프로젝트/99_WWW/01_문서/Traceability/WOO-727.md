# WOO-727 · Native Workbench Login

## 관찰

Legacy shell에는 `/login`, `/logout`, Provider 선택, `AuthFlowOverlay` 연결이 있었다. Native Workbench 명령 파서는 인증 명령을 인식하지 않았고 shell dependency에도 `AuthController`가 없어 현재 제품 화면에서 로그인 흐름을 시작할 수 없었다.

## 설계

`runApp`이 파일 자격 증명 저장소와 모델 registry를 사용해 `AuthService`를 만들고 Workbench shell에 주입한다. Workbench 명령은 다음 세 경로만 소유한다.

1. `/login`: Provider 선택 overlay
2. `/login <provider>`: 지원 로그인 방식 선택과 OAuth/API key 흐름
3. `/logout <provider>`: 해당 Provider 인증 삭제

실행 중인 응답이 있으면 인증 mutation을 시작하지 않고 현재 응답 뒤 다시 시도하도록 안내한다. 로그인 성공과 로그아웃 뒤에는 usage snapshot을 즉시 갱신한다.

## 보안·예외

API key 입력은 기존 `AuthFlowOverlay`의 secret masking을 사용한다. OAuth URL과 device code는 provider가 제공한 공개 안내만 표시한다. Esc·Ctrl+C·Ctrl+D는 인증 흐름을 abort하고 Workbench 입력으로 돌아간다. 인증 실패는 overlay 안에 격리하며 기존 Native thread를 종료하지 않는다.
