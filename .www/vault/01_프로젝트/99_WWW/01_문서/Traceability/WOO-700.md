# 목적

새 입력 뒤 공개 Plan이 준비·수신·진행되는 과정을 현재 세션 Todo에 자동으로 나타내는 요구를 기록한다.

# 배경과 결정

계획 없음과 0/0 완료를 구분하고, Native가 공개하지 않은 항목은 만들지 않는다. 공통 갱신 배선은 이 이슈가 소유하며 모델별 결속은 WOO-701, 영속성은 WOO-702가 소유한다.

대표 후보는 `src/application/todo-ledger.ts`의 이름 있는 최상위 class `TodoLedger`다. 현재 선언과 traceability-v2 원장에는 Code-011이 아직 없으며, 이 UUID는 향후 원장 등록을 위한 초안 값이다.

스냅샷 기준 상태는 `Todo`, parent는 `WOO-682`이며 제목과 보호 메타데이터는 변경하지 않는다.

# 상세 동작

ProjectWorkbench는 현재 active turn의 plan update 또는 해당 step 실행 activity만 Todo sync queue에 넣는다. sync 전 `syncing`, 성공 뒤 `confirmed`를 publish한다. WorkspaceTodoView는 active turn인데 문서가 없으면 ‘공개 계획을 기다리는 중’, 실행이 없으면 ‘현재 계획 없음’을 표시하며 42열 미만에서는 한 항목과 숨김 수를 보인다.

# 예외

다음 입력 뒤 이전 Plan을 현재로 남기거나, 빈 Plan을 완료로 표시하거나, foreign turn activity로 갱신하면 안 된다. 갱신 실패는 WOO-703 상태로 분리한다.

# 테스트 방법

Native Plan transport와 TodoLedger mirror 테스트로 input→plan→execution 갱신과 replay를 확인한다. 긴 한글·emoji·빈/완료/차단 Plan은 40·80·120열 실제 렌더와 Native TUI로 확인한다.

# 실제 결과

자동 sync 호출, plan 대기/없음 문구, 좁은 폭 한 항목 우선과 숨김 수 구현이 확인됐다. 관련 Todo 묶음은 121 pass/1 fail이며 이 이슈의 자동 갱신 자체 실패가 아니라 WOO-703 오류 문구 기대 불일치다. 실제 사용자 입력부터 화면 갱신까지의 시각 근거는 없다.

# 남은 항목

새 input 전환에서 이전 Plan 제거, 실제 무새로고침 갱신 시각, 40·80·120열 전체 목록 접근과 Native TUI 근거를 남겨야 한다.
