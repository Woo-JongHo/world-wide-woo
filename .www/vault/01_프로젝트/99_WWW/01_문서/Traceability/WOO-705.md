# 목적

동일 itemId와 비슷한 제목이 반복돼도 exact activity와 같은 thread·turn의 Plan 근거만 선택하는 identity 요구를 기록한다.

# 배경과 결정

관측 identity와 Plan association의 증거 수준을 나눈다. itemId·순번·제목·recency는 단독 identity가 아니며 partial journal은 provider 전체 복원으로 간주하지 않는다.

대표 후보는 `src/application/development-service.ts`의 이름 있는 최상위 class `DevelopmentService`다. 현재 선언과 traceability-v2 원장에는 Code-012가 아직 없으며, 이 UUID는 향후 원장 등록을 위한 초안 값이다.

스냅샷 기준 상태는 `In Progress`, parent는 `WOO-681`이며 제목과 보호 메타데이터는 변경하지 않는다.

# 상세 동작

`resolveActivitySelection`은 exact ID의 0/1/복수와 thread를 검사한다. `resolveTraceSelection`은 execution context, Plan source, turn/item ref, 단일 associated step을 확인한다. 결과는 observed identity, inferred/null planAssociation, planItemId, observed sequence coverage를 포함한다.

# 예외

없는 activity, duplicate ID, thread/turn mismatch, missing refs, Plan unavailable, membership mismatch, ambiguous association을 각 failure code로 반환한다. 선택 실패는 UI state를 변경하지 않는다.

# 테스트 방법

`test/trace-selection.test.ts`의 동일 itemId 두 turn과 partial journal/mismatch fixture를 실행하고 모든 failure code를 추가 mutation으로 확인한다. 화면에서 실패 뒤 selectedActivityId가 유지되는지도 검사한다.

# 실제 결과

전용 테스트 2 pass/0 fail이며 서로 다른 turn의 같은 itemId가 exact activity로 분리되고 partial journal에 `outside_observed_journal` coverage가 남는다. 모든 failure code와 실제 화면 격리는 아직 전부 검증되지 않았다.

# 남은 항목

duplicate·missing ref·ambiguous association 전용 사례, Workbench/Monitor/Tracer 화면별 오선택 방지, Code-012 등록을 완료해야 한다.
