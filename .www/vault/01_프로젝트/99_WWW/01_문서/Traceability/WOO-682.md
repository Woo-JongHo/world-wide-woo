# 목적

사용자 입력에 대한 공개 Plan과 모델·agent 작업을 현재 세션 Todo에서 실시간 확인하고 재개하는 통합 요구를 기록한다.

# 배경과 결정

Todo는 읽기 전용 Native Plan projection이다. 세션별 파일과 실행 참조를 보존하지만 전체 실행·승인은 Monitor, 상세 근거는 Tracer가 소유한다. Plan 완료·모델 종료·업무 수락은 별개다.

대표 후보는 `src/application/todo-ledger.ts`의 이름 있는 최상위 class `TodoLedger`다. 현재 선언과 traceability-v2 원장에는 Code-011이 아직 없으며, 이 UUID는 향후 원장 등록을 위한 초안 값이다.

스냅샷 기준 상태는 `In Progress`, parent는 `WOO-674`이며 제목과 보호 메타데이터는 변경하지 않는다.

# 상세 동작

`TodoLedger.syncNativePlan`은 source authority를 검증하고 최대 12개 step을 안정 ID로 TodoDocument에 투영한다. `ProjectWorkbench.enqueueNativeTodoSync`는 syncing/confirmed/blocked 상태를 게시하면서 Chat을 차단하지 않는다. `WorkspaceTodoView`는 폭 42열 미만에서 현재·다음·차단 항목을 우선하고 숨김 수, 주 실행 model/agent/run, 결속된 delegation task와 미확정 개수를 표시한다. thread별 Todo.md는 session factory에서 분리된다.

# 예외

누락·forged source, identity prefix 충돌, 늦은 다른 thread Plan, CAS 충돌은 저장 전에 또는 저장 경계에서 fail-closed해야 한다. 관측되지 않은 model/agent는 null 또는 미확인으로 남긴다.

# 테스트 방법

Todo 관련 네 파일을 실행해 Plan mirror, stable ID, source authority, 두 세션 파일, resume, CAS conflict, UI projection을 확인한다. 실제 다중 모델 Native 실행과 40·80·120열 화면은 별도 수동 근거로 남긴다.

# 실제 결과

Todo 관련 실행은 121 pass/1 fail이다. 실패는 `project-workbench-session.test.ts`가 내부 오류 문자열 `sync rejected` 노출을 기대하지만 구현은 사용자용 요약을 표시하는 불일치다. 나머지 테스트에서 session 분리, model reference, replay 억제, CAS 재읽기가 확인됐다. 전체 실제 TUI 수락은 아니다.

# 남은 항목

오류 문구 회귀 기대를 현재 안전한 UX 계약과 맞추고, Code-011 등록, 실제 병렬 모델·agent 관측, 좁은 폭·재개·실패 복구의 Native TUI 근거를 완료해야 한다.
