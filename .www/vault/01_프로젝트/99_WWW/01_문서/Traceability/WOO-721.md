# 목적

Todo의 source·identity·저장·재개 예외가 durable 계획과 다른 세션을 오염시키지 않도록 실패·보존·복구 계약을 기록한다.

# 배경과 결정

예외 처리는 정상 동작을 복제하지 않고 fail-closed 조건과 사용자 영향, 보존 데이터, 지원되는 다음 행동을 모은다.

대표 후보는 `src/application/todo-ledger.ts`의 이름 있는 최상위 class `TodoLedger`다. 현재 선언과 traceability-v2 원장에는 Code-011이 아직 없으며, 이 UUID는 향후 원장 등록을 위한 초안 값이다.

스냅샷 기준 상태는 `Backlog`, parent는 `WOO-682`이며 제목과 보호 메타데이터는 변경하지 않는다.

# 상세 동작

검증 단계에서 Native source authority와 item identity를 확인하고, commit 단계에서 CAS expected revision을 사용한다. 충돌이면 store를 다시 읽어 current snapshot을 durable 값으로 바꾸고 pending patch 및 가능한 source를 TodoWriteConflictError에 보존한다.

# 예외

forged/missing source, prefix collision, late/foreign Plan, read failure, external edit, model/agent 미관측을 별도 사례로 다룬다. 어느 경우에도 기존 문서나 Chat draft를 지우지 않는다.

# 테스트 방법

TodoLedger invalid source/collision/late source/CAS/external watch 테스트와 project-workbench 실패 표시를 실행한다. mutation 전후 store write 수와 event 수, snapshot, 사용자 안내를 비교한다.

# 실제 결과

잘못된 source와 ID는 쓰기 전 거부되고 CAS 뒤 durable 문서를 재읽는 테스트가 통과했다. 전체 Todo 실행에는 사용자용 오류 문구와 오래된 테스트 기대 불일치 1건이 있다.

# 남은 항목

오류 문구 테스트 정합화, read까지 실패한 충돌, 실제 외부 편집과 Native TUI 복구, Code-011 연결을 완료해야 한다.
