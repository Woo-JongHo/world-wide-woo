# 목적

wide·compact 배치 전환 뒤에도 같은 논리 패널과 읽던 근처 내용을 유지하는 요구를 기록한다.

# 배경과 결정

wide의 독립 viewport와 compact의 단일 ordered viewport를 같은 콘텐츠로 투영한다. 이 이슈는 위치·접근성을 소유하고 focus/overlay 복귀는 WOO-708이 소유한다.

대표 후보는 `src/presentation/tui/dashboard-layout.ts`의 이름 있는 최상위 function `createDashboardLayout`이다. 현재 이 선언은 Code-003에 등록되어 있으므로 Code-013 전환은 별도 원장·대표 선언 정합화가 필요하고, 이 UUID는 그 초안 값이다.

스냅샷 기준 상태는 `Todo`, parent는 `WOO-680`이며 제목과 보호 메타데이터는 변경하지 않는다.

# 상세 동작

createDashboardLayout은 88열·14행 이상에서 wide, 그 미만에서 compact를 활성화한다. `activate`는 전환 전 source viewport의 follow/anchor/fraction을 target에 넘긴다. compact 문서 순서는 left→rightTop→rightBottom이며 wide 우측은 7:3 grow 비율이다.

# 예외

anchor가 사라지거나 중복돼도 다른 패널로 튀지 않고 fraction fallback을 써야 한다. 높이만 낮아져 compact가 될 때도 모든 section이 scroll content에 남아야 한다.

# 테스트 방법

dashboard layout의 wide/compact/120×10/120×13 접근과 독립 scroll을 실행한다. 별도 전환 fixture로 120→80→40→120열에서 scrollTop·anchor·follow를 비교하고 한글·emoji 폭을 검사한다.

# 실제 결과

Layout 묶음 33 pass/0 fail이다. wide 세 viewport, compact 순서, 낮은 높이 접근, contained scroll이 검증됐다. 현행 테스트는 mode 전환 전후 실제 동일 anchor 복원을 직접 충분히 assert하지 않는다.

# 남은 항목

왕복 anchor/follow 전용 자동 테스트, 실제 resize·무채색·Unicode 화면 근거, Code-003에서 Code-013으로의 별도 원장 정합화가 필요하다.
