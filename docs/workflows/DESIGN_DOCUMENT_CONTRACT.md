# Design Document Contract

## 목적

여러 모듈의 API·저장 형식·책임 경계 변경에서 구현 전에 고비용 결정을 드러내고 검토한다. 설계 정본은 저장소 `docs/`에 둔다.

## 적용

여러 구현자가 협업하거나 장기간 이관·API/schema/identity 변경·다른 시스템과의 조정·데이터 손실 위험이 있으면 설계가 필요하다. 작은 수정은 기존 설명과 재현·회귀 검증으로 충분할 수 있다.

## 내용

- 목적과 관찰된 문제
- 범위와 인접 책임, 보존할 사용자 동작
- 상태·데이터 흐름과 모듈/CLI/설정 계약
- 채택한 결정과 실제로 고려한 대안, 선택 근거
- 미결 질문과 필요한 근거, 영향과 복구 방법
- 실행 순서와 측정 가능한 완료 조건

쉽게 교체할 구현 세부사항을 설계 의무로 확대하지 않는다. 확인된 사실·추정·미결 질문을 구분하고, 문서에 공개할 수 없는 자격증명을 포함하지 않는다.

## 검토와 변경

저작과 독립 검토는 다른 패스로 진행한다. 발견한 blocking 문제는 구현 전에 해결하거나 미실행 근거로 명시한다. 실행 뒤 실제 변경과 검증 근거를 문서에 반영한다. 외부 업무 관리 서비스의 연결이나 게시를 설계 완료 조건으로 요구하지 않는다.
