# 제품 개발 흐름

## 소유권

| 내용 | 소유 위치 |
|---|---|
| 사용자 요청과 실행 계획 | 현재 대화와 Native PLAN |
| 설계·결정·사용법 | 저장소 docs |
| 구현·변경 이력 | 소스와 Git |
| 실행 진행과 검증 | PROGRESS·TEST 및 로컬 Evidence |
| 승인된 공개 이슈·PR | GitHub |

## 실행

요청을 이해하고 필요한 경우 Native 실행 계획을 만든다. 작업을 수행하면서 실제 진행과 명령의 의도를 표시한다. 변경 이유에 맞는 테스트를 실행하고 유형·목적·결과를 보고한다. 설계와 코드·검증의 실제 차이를 확인한 뒤 남은 미검증을 명시한다.

Linear·WES·Obsidian 연결·게시·계층·추적성 원장 정합은 개발 진입이나 종료의 조건이 아니다. 과거 관리 구조는 `docs/archive/retired-work-management/`에서 역사로 보존한다.
