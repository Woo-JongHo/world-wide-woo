# 목적

Tracer 선택·Plan 결속·Source 공개 경계의 예외가 오선택과 정보 노출로 번지지 않도록 기록한다.

# 배경과 결정

각 실패는 원인과 coverage를 가진 결과로 남고, 다른 activity로 자동 대체하거나 provider 전체 이력을 복원했다고 주장하지 않는다.

대표 후보는 `src/application/development-service.ts`의 이름 있는 최상위 class `DevelopmentService`다. 현재 선언과 traceability-v2 원장에는 Code-012가 아직 없으며, 이 UUID는 향후 원장 등록을 위한 초안 값이다.

스냅샷 기준 상태는 `Backlog`, parent는 `WOO-681`이며 제목과 보호 메타데이터는 변경하지 않는다.

# 상세 동작

domain resolver는 activity_not_found부터 ambiguous_plan_association까지 구조화된 코드를 제공한다. selectedSourceRows는 선택 없음과 원본 부재를 나누고 boundedPublicProjection으로 payload를 제한한다.

# 예외

duplicate ID, missing turn/item, thread/turn mismatch, partial journal, orphan association, 긴/민감/ANSI payload를 포함한다. 실패 뒤 selectedActivityId·draft·다른 화면은 보존한다.

# 테스트 방법

trace-selection mutation, Workbench Source unavailable/partial fixture, delegation orphan과 긴 payload 정제를 실행한다. 실제 TUI에서 실패 뒤 동일 화면·입력 복귀를 확인한다.

# 실제 결과

동일 itemId 격리와 partial/mismatch 전용 테스트 2건, 관련 Tracer 테스트 36건이 통과했다. 모든 failure code와 실제 화면 복구는 아직 전부 확인되지 않았다.

# 남은 항목

전체 failure code matrix, 공개 정제 경계, 화면별 선택 보존, Code-012 원장 연결과 실제 Native TUI 근거가 남아 있다.
