# 목적

세션별 Todo.md가 입력·turn·Plan revision·실행 참조를 보존하고 재개에서도 같은 할 일을 가리키는 요구를 기록한다.

# 배경과 결정

thread 기반 세션 key가 저장 소유권을 갖고, 문서 revision과 화면 순번은 item identity가 아니다. 기존 참조 없는 문서는 호환 읽기하되 관측하지 않은 정보를 채우지 않는다.

대표 후보는 `src/application/todo-ledger.ts`의 이름 있는 최상위 class `TodoLedger`다. 현재 선언과 traceability-v2 원장에는 Code-011이 아직 없으며, 이 UUID는 향후 원장 등록을 위한 초안 값이다.

스냅샷 기준 상태는 `In Progress`, parent는 `WOO-682`이며 제목과 보호 메타데이터는 변경하지 않는다.

# 상세 동작

TodoLedger는 64자 Plan identity에서 `native-`+48자 ID를 만들고 prefix 충돌을 거부한다. source에는 input activity/request/digest, Plan revision, root execution을 저장한다. 같은 content는 재쓰기하지 않고 late/foreign source는 `canApplyNativeSource`에서 거른다. session factory는 thread별 `.www/todos/<session-key>/Todo.md` 경로를 사용한다.

# 예외

forged source, 잘못된 digest, duplicate identity, 다른 thread의 늦은 Plan은 쓰기와 event 전에 거부한다. CAS 충돌은 현재 durable 문서를 재읽고 pending 변경과 분리한다.

# 테스트 방법

TodoLedger의 삽입·재정렬·edit·replay 및 invalid source 테스트와 project-workbench-session의 두 thread 파일·resume 최신 Plan 테스트를 실행한다. 저장→재개 round-trip에서 model/agent null도 대조한다.

# 실제 결과

결정론적 ID, source validation, replay 억제, late/foreign 무시, 두 thread의 별도 경로와 모델 참조가 테스트로 확인됐다. Todo 테스트 묶음의 1개 실패는 저장 포맷이 아니라 WOO-703 오류 표시 기대다.

# 남은 항목

기존 참조 없는 실제 파일 호환, 외부 편집과 resume 장기 시나리오, Code-011 원장 연결과 Native TUI readback 근거를 완료해야 한다.
