# WOO-679 · Chat 전체 흐름

## 목적

질문·답변·실행 결과를 한 흐름으로 읽고 다시 찾는다.

## 배경과 결정

기존 상세는 ../Chat/WOO-679.md에 보존한다. 이 노트는 v2 ID 그래프의 정본 연결만 추가한다.

Linear에는 목적·결과·범위·동작·완료 조건과 연결만 둔다. Code-ID는 평문 `Code-001`이며 대표 선언의 `@Unit Code-001`로 찾는다.

## 상세 동작

원장의 Issue UUID, Unit UUID, Vault 상대 경로를 함께 검증한다. SQLite는 동일 원장의 digest로 재구축하며, Development Map은 그 투영을 사람이 읽는 표로 생성한다.

plain `www`는 Astra Execution Console을 열고 현재 Workbench snapshot을 사용하는 WWW Dashboard에서 시작한다. Chat은 `TUI-F002` 아래의 세부 Unit으로 조회되며, `TUI-F002-U08`은 공개 user·assistant 메시지에서 최대 6개·1,400자 범위의 Conversation Recap을 투영한다. system·reasoning·tool payload는 Recap 입력에서 제외하고 별도 상태로 저장하지 않는다.

TUI의 기본 본문 글자는 흰색을 사용한다. 상태와 역할 색상은 제목·표식에만 적용하여 본문의 기본 가독성을 유지한다.

## 예외

ID 중복·별칭 재사용·끊어진 edge·stale 코드 위치·잘못된 frontmatter·오래된 SQLite·Map diff는 정상 결과로 숨기지 않고 gate 실패로 반환한다.

## 테스트 방법

`bun run traceability:check`로 원장, AST, Obsidian, SQLite rebuild, Map freshness를 한 번에 확인한다. mutation fixture에서 각 연결을 하나씩 끊어 gate가 실패하는지도 확인한다.

CLI·Dashboard·Recap은 `test/cli.test.ts`, `test/astra-shell.test.ts`, `test/entry-dashboard-view.test.ts`, `test/conversation-recap.test.ts`, `test/tui-feature-registry.test.ts`로 검증한다. 전체 회귀와 아키텍처·Code-ID·Unit 검사를 함께 통과해야 한다.

## 실제 결과

검증 결과와 명령 출력은 `.www/evidence/v020-traceability/verification.json` 및 같은 디렉터리의 로그에 기록한다.

## 남은 항목
