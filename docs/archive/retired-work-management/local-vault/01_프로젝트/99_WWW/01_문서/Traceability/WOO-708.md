# 목적

작은 화면과 overlay·보조 화면 이후에도 Composer focus와 draft, 다음 조작을 복원하는 요구를 기록한다.

# 배경과 결정

editable focus의 일반 키와 observability navigation shortcut을 분리한다. overlay 닫기와 승인 결정은 별개이며 Layout은 공통 복귀 상태만 소유한다.

대표 후보는 `src/presentation/tui/dashboard-layout.ts`의 이름 있는 최상위 function `createDashboardLayout`이다. 현재 이 선언은 Code-003에 등록되어 있으므로 Code-013 전환은 별도 원장·대표 선언 정합화가 필요하고, 이 UUID는 그 초안 값이다.

스냅샷 기준 상태는 `Todo`, parent는 `WOO-680`이며 제목과 보호 메타데이터는 변경하지 않는다.

# 상세 동작

Workbench shell은 Workbench·Source·Monitor·Dashboard·Stats를 sibling mode로 두고 Esc를 workbench 복귀로 매핑한다. observability shortcut은 editable focus에서 처리하지 않는다. Source 진입은 source layout viewport에 focus를 준다. overlay는 별도 입력 handler를 사용한다.

# 예외

낮은 높이에서 Composer가 접근 불가능해지거나, Esc가 승인으로 해석되거나, 새 출력 중 editor 내용이 지워지면 안 된다. 복귀 대상이 사라질 경우 안전한 기본 focus가 필요하다.

# 테스트 방법

workbench shell policy, approval/model overlay 테스트와 실제 40·80·120열/낮은 높이에서 작성→overlay→보조 화면→Esc를 연속 실행한다. 각 단계 draft·focus owner·pending approval을 기록한다.

# 실제 결과

Layout·shell policy 묶음 33 pass/0 fail이며 sibling navigation과 editable shortcut 억제 정책이 있다. 실제 IME·작은 높이·overlay 왕복에서 focus owner와 draft를 입증한 통합 화면 근거는 확인되지 않았다.

# 남은 항목

실제 focus 상태 측정, overlay 닫기 무결성, 낮은 높이와 새 출력 중 draft 보존, Code-013 원장 정합화를 완료해야 한다.
