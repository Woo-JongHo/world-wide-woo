# WWW와 기존 도구의 경계

WWW의 목적은 사용자가 선택한 모델의 작업을 관찰하고, 필요할 때 모델 사이의 검토와 실패 대체를 명시적으로 연결하는 것이다.

GJC는 provider 연결과 인증 구현을 참고할 수 있는 소스다. 필요한 부분만 라이선스·원저작권 고지와 함께 검토해 채택한다. 전체 agent framework를 복제하는 것은 현재 제품 요구가 아니다.

Pi AI는 현재 WWW의 다중 모델 실행 경로가 사용하는 라이브러리다. Pi coding agent는 별도의 내장 실행 lane에 쓰이지만, 최종 제품의 기본 오케스트레이션을 Pi의 agent loop에 맡긴다는 결정은 아니다. 전환 시 각 import와 기능을 기준으로 유지 여부를 판정한다.

OMO와 OMX는 배포 종속성 또는 필수 작업 절차가 아니다. WWW 사용자에게 그 도구를 설치하도록 요구하지 않는다. WOO 개발자가 사용하는 스킬·훅·이슈 기록 절차도 WWW 제품 기능과 구분한다.

현재 코드에는 위 경계에 맞지 않는 의존성과 레거시 명령이 남아 있다. 실제로 제거되기 전까지 경량 배포가 완료됐다고 기록하지 않는다. [제품 방향](WWW_PRODUCT_DIRECTION.md)의 구현 표가 현재 상태를 소유한다.
