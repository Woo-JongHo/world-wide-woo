# WWW Entry

저장소와 Linear의 대상을 확인한 뒤 사용자가 요청한 작업을 이어간다.

## 위치와 정본

1. `pwd`, `git status --short --branch`, `git rev-parse --show-toplevel`로 작업 위치·브랜치·기존 변경을 확인한다. 본문의 저장소 경로는 루트 기준, Markdown 링크는 이 파일 기준이다.
2. 루트 `AGENTS.md`를 읽는다. 머신 방법론이 필요하면 `~/.codex/woo.yaml`의 `workspace_root`를 해석해 해당 정본을 읽는다. 이 경로는 제품 저장소와 다를 수 있다. 파일이 없으면 누락 사실을 보고하고 경로나 머신 설정을 임의로 바꾸지 않는다.
3. `.www/project.json`의 로컬 이름을 확인한다. `.www/control-ledger/development/project.json`의 ID는 로컬 개발 원장 ID이며 Linear 프로젝트 UUID로 사용하지 않는다.

## Linear 연결

연결 대상의 정본은 `.www/linear-project.json`이다. 이 파일은 Entry 스킬이 읽는 연결 기록이며 앱의 자동 동기화 설정은 아니다.

기록의 `mcpServer`에 해당하는 도구를 우선 선택한다. 같은 Linear 서비스여도 다른 MCP나 앱 커넥터는 다른 워크스페이스로 인증되어 있을 수 있다. 도구가 현재 세션에 노출되지 않으면 로컬 MCP 등록·인증 상태와 세션의 도구 가용성을 구분해 보고한다. 다른 연결을 재인증하기보다 등록된 대상 MCP를 사용할 수 있는 세션에서 확인한다.

- 파일이 있으면 `workspace.id`, `project.id`로 연결된 워크스페이스와 프로젝트를 다시 조회한다. 응답 ID와 프로젝트 URL의 워크스페이스가 기록과 일치해야 연결 확인으로 판정한다. 불일치하면 기록을 덮어쓰지 않고 대상 확인·연결 복구를 요청한다. 이름 변경은 UUID를 기준으로 확인한다.
- 파일이 없으면 사용자가 지정한 워크스페이스·프로젝트와 현재 조회 결과의 이름·URL을 대조한다. 지정이 불충분하면 로컬 기록으로 후보를 찾고 대상을 묻는다. 목록은 다음 페이지가 없어질 때까지 확인한다. 기존 기록은 후보를 찾는 단서이며 현재 접근 가능하다는 증거는 아니다.
- 후보가 없거나 모호하거나, 조회된 워크스페이스가 사용자가 지정한 대상과 다르면 대상 선택 또는 해당 MCP의 연결 복구를 요청한다. 이 상태에서는 프로젝트를 새로 만들거나 기존 연결을 덮어쓰지 않는다. Linear와 독립적인 로컬 작업은 계속한다.
- 사용자가 요청한 연결 대상이 확정되고 실제 조회가 성공하면 아래 필드를 기록한다. 자격 증명은 저장하지 않는다. 저장 후 파일을 다시 읽어 응답과 대조한다.

| 필드 | 값의 출처 |
|---|---|
| `schemaVersion` | `1` |
| `mcpServer` | 실제 조회에 사용한 MCP 서버 이름 |
| `workspace.id`, `workspace.name`, `workspace.url` | 현재 워크스페이스 조회 응답 |
| `project.id`, `project.name`, `project.url` | 확정한 프로젝트 조회 응답 |
| `verifiedAt` | 실제 확인 시각의 ISO 8601 값 |

새 프로젝트 생성은 사용자가 대상 워크스페이스를 지정해 신규 생성을 요청하고 현재 연결도 그 대상과 일치할 때 수행한다. 생성 후 같은 조회·저장 절차를 적용한다. 연결 확인만으로 프로젝트 생성이나 이슈·본문·상태 변경 권한을 확장하지 않는다.

## 요청 실행

`AGENTS.md`의 코드 구조·Linear·Obsidian·Git 규칙이 지정한 스킬을 읽고 적용한다. 작업 진입 항목은 이미 수행한 것으로 보고 Entry에 재진입하지 않는다. Entry에 게시·승인·계층 계약을 복제하지 않는다.

- 개발 현황 지도: [development-map](../development-map/SKILL.md)
- 코드·Linear·Obsidian 간 연결 검사: [development-traceability](../development-traceability/SKILL.md)
- RPA 신규·유지보수: [rpa-intake](../rpa-intake/SKILL.md)에서 사실을 확인한 뒤 해당 흐름으로 진입한다.
- 코드 모듈·의존 경계 변경: 루트 `LAYERS.md`를 먼저 읽는다.

진입 결과는 현재 저장소·브랜치, Linear 프로젝트와 확인 상태, 이어서 적용할 스킬, 실제 막힌 항목만 짧게 알린다. 사용자가 상태 확인만 요청한 경우를 제외하면 진입 보고 뒤 원래 작업을 계속한다.
